# Stylelint suppressions — what is off, re-scoped, or excepted, and why

JSON has no comments, so the reasons for every deviation from
`stylelint-config-standard` in [`.stylelintrc.json`](.stylelintrc.json) live
here. Reviewed in full for `chore-design-tokens` (2026-10-08): 15 rules were
disabled outright; now 1 is, 2 are re-scoped with options, and 3 keep a single
annotated site each. Re-run the census before changing any of these:

```sh
cd web && npx stylelint "src/**/*.css" -f json -o /tmp/census.json   # with the rule enabled
```

## Still disabled

| Rule | Why it stays off |
|---|---|
| `media-feature-range-notation` | Autofix rewrites `(max-width: 768px)` to `(width <= 768px)`. Browsers that predate range syntax (Safari before 16.4, Chrome before 104) ignore such a media query **entirely**, so every responsive block would silently drop on older phones. That is a browser-support-floor decision, not a style one; re-enable only alongside an explicit decision to drop those browsers. 9 sites. |

## Re-scoped with options

| Rule | Option | Why |
|---|---|---|
| `selector-class-pattern` | kebab-case BEM regex: `block`, `block__element`, `block--modifier` | `developers-react.md` §7.3 asks for kebab-case prefixed with the component root; the codebase does that in BEM form (`.hero__panel`, `.event-card--fire`), which the stock kebab-case pattern rejects (102 sites). The regex encodes the actual convention instead of waiving it. |
| `property-no-vendor-prefix` | `ignoreProperties: ["-webkit-backdrop-filter", "-webkit-mask-image"]` | Safari needed `-webkit-backdrop-filter` until 18 and `-webkit-mask-image` until 15.4; the prefixed fallbacks stay next to the unprefixed declarations. ⚠️ The ignore list matches the **full prefixed name**: `"backdrop-filter"` is silently ignored, and with that misconfiguration the autofix deleted all four fallbacks in one pass. Caught by the declaration-count check, not by the lint. |

## Enabled with an annotated exception at the site

Each site carries `/* stylelint-disable-next-line <rule> -- <reason> */` so the
reason travels with the code.

| Rule | Site(s) | Reason |
|---|---|---|
| `scale-unlimited/declaration-strict-value` | `margin: -1px` in `.sr-only` (EventsDashboard.css) and `.select__label` (Select.css) | The visually-hidden idiom pulls a 1px box out of flow; `-1px` is not spacing and must not become a token. |
| `property-no-deprecated` | `clip: rect(0, 0, 0, 0)` in the same two rules | `clip` is the widest-supported form of the idiom. `clip-path: inset(50%)` is its modern pair and can replace it once the support floor moves. |
| `declaration-property-value-keyword-no-deprecated` | `word-break: break-word` in `.event-location` (EventsDashboard.css) | Deprecated in favour of `overflow-wrap: anywhere`. Swapping changes wrapping on real overflow and needs its own verification on long place names; this refactor is values-only. |

## z-index policy encoded in the lint

`z-index` is governed by `declaration-strict-value` with `-1`, `0`, `1` and `2`
allowed as literals. Those are local stacking inside a contained context —
the hero graticule behind the hero content, the signal-dot ring behind its dot
(`isolation: isolate`), the milestone rail behind the milestone dots, a map
marker's badge over its pointer. Anything outside that range is a global layer
and must be one of the `--z-*` tokens in `tokens.css`. Seven literal sites,
audited 2026-10-08; see `chore-design-tokens` task 3.2.

## Re-enabled outright (no exceptions needed)

`custom-property-pattern`, `no-descending-specificity` (three rules reordered;
each pair was either mutually exclusive or set disjoint properties, so the
cascade result is unchanged), `color-function-notation`,
`color-function-alias-notation`, `alpha-value-notation`, `color-hex-length`
(notation autofix in `tokens.css` only, verified pixel-identical),
`rule-empty-line-before`, `comment-empty-line-before`,
`declaration-block-single-line-max-declarations` (three keyframe/media blocks
reformatted), `length-zero-no-unit`.
